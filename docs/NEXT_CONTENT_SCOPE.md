## 1. 목표와 완료 기준 (로드맵 Phase 2)

- 목표: 관리자가 **이슈 선택 → (LIFE 후보 확인) → 제목 후보 → 초안 생성 → 편집 → 출처·관련 URL 확인 → 검수 승인**까지 한 화면 흐름으로 처리한다.
- 완료 기준(명세): "관리자가 이슈 선택부터 검수 가능한 초안 완성까지 한 화면 흐름으로 처리할 수 있다." 확인할 것: AI 문장 품질보다 **관리자가 실제로 시간을 절약하는지**.

## 2. 기존 이슈 요약과 새 콘텐츠 제작의 구분

| | 지금 있는 이슈 요약 (Phase 1) | 새 콘텐츠 제작 (Phase 2) |
|---|---|---|
| 데이터 | `issue.title/summary/key_facts`(+ `title_source`/`summary_source` AUTO·MANUAL) | 새 `content`(NEWS·LIFE), `content_source`(근거 N:M), `content_link`(관련 URL) |
| 만드는 주체 | 기사 분석 결과를 모아 자동 갱신(멤버십이 바뀔 때마다 재계산), 관리자 수정 가능 | 관리자가 이슈를 골라 생성 요청 → AI 초안(DRAFT) → 관리자 편집 |
| 상태 | 이슈 상태 `ACTIVE/REVIEW/MERGED/CLOSED/EXCLUDED`(사건 묶음의 상태) | 콘텐츠 상태 `DRAFT/REVIEW/APPROVED/HOLD/EXCLUDED/ARCHIVED`(편집·검수 상태만). AI 진행·실패는 `async_job`, 발행 상태는 콘텐츠에 넣지 않음 |
| 공개 | 뉴스룸(`/news`, `/api/public/issues`)이 ACTIVE·CLOSED 이슈 요약을 보여 줌 | 이번 범위에서는 공개하지 않음(공개 콘텐츠 API·발행은 Phase 3/5) |
| 관계 | 하나의 이슈에서 NEWS 콘텐츠와 LIFE 콘텐츠를 각각 만들 수 있음(명세 §생활 이야기) | 콘텐츠 수정이 이슈 요약을 바꾸지 않고, 이슈 요약 재계산이 콘텐츠 본문을 바꾸지 않는다 |

## 3. 이번 범위 / 제외

포함: LIFE 후보 판정, 제목 3종 추천, NEWS·LIFE 초안 생성, 콘텐츠 편집(제목·소제목·문단 추가·삭제·순서·자동저장), 출처 확인, 상태 관리(검수), 관련 URL 관리, 관리자 화면.

제외(사용자 지시·명세 단계): 회원 기능, TV·지역(Phase 4), 외부 블로그 발행(Phase 5), ERDCloud, 자체 사이트 발행·공개 콘텐츠 API(Phase 3), SEO·링크 상태 검사·성과 분석(Phase 6), 이미지 관리·생성(후순위), 특정 문단 AI 재작성(명세상 후순위), 블로그 미리보기.

## 5. 검증 원칙 (기존 규칙 유지)

- 생성 품질은 사람이 정답·검토 기준을 먼저 정한 평가로 확인한다. stub 결과를 품질 근거로 쓰지 않는다.
- 평가 정답이나 합격 기준을 결과에 맞춰 완화하지 않는다. 프롬프트에 평가 사례를 하드코딩하지 않는다.
- 유료 호출은 작업마다 호출 수·금액 한도를 정하고, 예상 비용과 기록된 추정 비용을 구분해 보고한다.
- AI 결과는 항상 DRAFT로 저장하고 자동 발행하지 않는다(명세).

## 6. 결정 필요 (명세에 없거나 모호한 것 — 임의로 정하지 않음)

> **2026-10-15 사용자 결정 반영:** 1(상태 흐름 DRAFT→REVIEW→APPROVED, 승인 후 수정 시 DRAFT), 2(구조화 JSON), 5(ACTIVE·CLOSED만, 같은 유형 여러 개 허용 + 중복 생성 방지), 6(본문 자동 덮어쓰기 없음, 업데이트 필요 표시), 8(변경 시에만 자동저장, version 충돌 409), 9(미리보기 제외), 12(embedding 열 만들지 않음)는 정해졌다. 구체 계획과 남은 결정은 [CONTENT_A_PLAN.md](CONTENT_A_PLAN.md). 3·4·7·10·11은 B·C 묶음에서 결정.

1. **콘텐츠 상태 전이 규칙**: DRAFT → REVIEW → APPROVED 순서가 필수인지, DRAFT에서 바로 승인 가능한지, HOLD·EXCLUDED·ARCHIVED에서 어디로 돌아갈 수 있는지, 승인 후 수정하면 상태가 어떻게 되는지. 승인 권한(OPERATOR/SYSTEM_ADMIN) 구분.
2. **본문 저장 형식**: 명세는 "제목/본문/소제목, 문단 추가·삭제·순서 변경"만 정함. 섹션 목록(JSON: 소제목+문단 배열) / Markdown / HTML 중 선택. 문단 순서 변경·부분 재생성을 생각하면 섹션 구조가 유리하나 결정 필요.
3. **LIFE 카테고리 목록과 후보 기준점수**: 명세 예시는 "노인안전" 하나와 "생활·안전·가족·소비·기술". 고정 목록과 relevanceScore 기준값.
4. **LIFE 판정 대상**: 모든 ACTIVE 이슈를 자동 판정할지, 관리자가 고른 이슈만 판정할지(유료 호출 수에 직접 영향).
5. **콘텐츠를 만들 수 있는 이슈 상태**: ACTIVE만 허용할지(검수 대기 REVIEW 이슈 제외 권장), CLOSED 포함 여부. 같은 이슈에서 같은 유형 콘텐츠를 여러 개 허용할지.
6. **이슈가 바뀐 뒤의 콘텐츠**: 콘텐츠 생성 후 원천 이슈가 병합·분리·새 기사 추가되면 알림만 할지, "업데이트 필요" 표시할지(명세 대시보드 KPI에 "업데이트 필요 콘텐츠 수"가 있음).
7. **원문 복사 비율 기준값**: "과도하지 않은지"의 수치(예: 연속 n어절 일치 비율)와 초과 시 처리(경고/REVIEW).
8. **자동저장 주기와 충돌 처리**: 저장 간격, 두 창에서 동시 편집 시 처리(마지막 저장 우선 / 충돌 안내).
9. **사이트 미리보기**: Phase 3 공개 콘텐츠 화면이 없으므로 이번에는 관리자 화면 안의 단순 미리보기로 할지, 제외할지.
10. **제목 후보 보관**: 추천 이력(다시 추천한 이전 후보)을 저장할지, 선택한 제목만 남길지.
11. **글쓰기 모델·비용 한도**: 짧은 분류(gpt-4o-mini)와 긴 글쓰기에 다른 모델을 쓸지(명세 07 "검토"), 콘텐츠 1건당 허용 비용.
12. **`content.embedding`**: 명세 ERD에 있으나 용도(관련 콘텐츠 추천)는 Phase 3. 이번에 컬럼만 둘지 뺄지.
